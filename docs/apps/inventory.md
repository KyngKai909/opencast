# Inventory of the reference designs

Phase 0 of the apps prompt. For every frame in every file in `docs/reference/`: the app, the route, the components, the data (the contract endpoint and the fields behind the frame), and its states. It also lists each Open item, what can't be built as drawn, and what the contracts don't cover yet.

**How it was made.** Each reference file was rendered in Chrome, and its sections, frames (size, caption, headings, full visible text) and notes were extracted. Every frame was then checked against the Zod schemas in `packages/contracts`, with each gap verified against the schema rather than an endpoint's summary. The token values were compared across all 21 files in both grounds.

## Decisions needed

These are the items that change what gets built. The per-app sections below have the rest, with frame references.

**Where pages live**

1. **The creator's permission page** goes in the viewer app at `/permission/:token`, outside the phone shell. The API already builds its link from `APP_ORIGIN` (the viewer), the desk is admin-only, and "Claim now" needs sign-in.
2. **The creator's claim page** ("CRAT 101.9 is ready for you") goes in master control at a public `/claim/:token`, since claiming ends in master control. No file places it.
3. **Station pages at `/:handle`.** Handles need to avoid the app's own routes (`guide`, `radio`, `you`, …), and studio handles need to avoid call signs. `createStation.handle` reserves nothing.

**Rules and states**

4. **Default ground.** The prompt says dark is the default and follows the system setting. The references default to light unless the system asks for dark. The proposal is dark when the system has no preference.
5. **A lit tally where nothing is on air.** The radio band list (station-pages 04.1) and the site's waitlist confirmation (S.11) light the tally. Both break the tally rule. The proposal is the tally edge in the list, and an unlit or no sign on the site.
6. **Numbers on the web.** Digits 1 to 6 are preset keys "from anywhere", and "numbers tune" anywhere a viewer can type. The proposal: outside a text field, digits are preset keys; channel numbers go through search (`/`).
7. **Spot states.** It's unclear what `waiting_for_you` means next to `paused_budget` (spots 04.1 shows both at once). Frame words also differ from `states.ts`: "Paused, budget spent", "In review, usually a few hours", the short phone tags, "Credited", and the order step rail's "Asked, Quoted". Either `states.ts` gets the frames' words and short forms, or they go in new-copy.
8. **Claim labels.** "Removed" is shared by `removed` and `expired`. "Answered, back on air" and "Removed by BEAT" appear in frames. The rights basis reads "We made it" in the claim and "I made it" in the library, and the note says the two must match.
9. **Roles the contracts leave open.** Who may offer terms, decide carriage requests, quote orders, answer claims (the attestation carries legal weight), approve sponsorships, sign off (the team table says owners; the API allows operators), and download a statement CSV (operators see earnings, but the CSV is owner-only). A host's rail is also undecided: disabled items, or a host-only rail.

**Design conflicts**

10. **Station ID position.** The Monitor rundown airs the station ID mid-break; the settings rule says it's always last.
11. **Watch on labels.** The phone's "Watch on" list says Chromecast and AirPlay with one button. Its note says "Cast", "Mirror" and "Open the app". iOS can't list AirPlay TVs itself, only through the system picker.
12. **Listed city streams on a TV.** They play the city's own embed, which a D-pad and a Cast receiver can't drive. Skip them on TV and Cast, or show a "watch on the city's player" state.
13. **The bug and title safe.** The style guide draws the bug at 3.5% and 7%, outside the 5% title safe it defines.

**Platform limits**

14. **Promises that need the native app.** These can't work in a web PWA and wait for Phase 8: lock-screen channel controls on iOS, the battery warning with minutes left, dead-air fixes from the lock screen, and Cast from iOS Safari.

**Undrawn screens**

15. **Screens described in notes but not drawn** need copy (listed in `new-copy.md`):
    - viewer: six of the eight settings panes;
    - master control: the maker's delivery, notes and dispute screens;
    - TV: four of the five settings sections;
    - desk: five rail pages;
    - every error and empty state not drawn.

#### Open items

- **Watch from the start** (home 03.1). Build so it's easy to change by keeping the player's "no seek" rule behind one `allowStartOver` capability in `packages/player` and leaving a slot on the tuned-in page and program page (station-pages 02.1) where a "From the start" action would go.
- **Opencast's share of pledges** (home 07.1). Build so it's easy to change by rendering the pledge summary line from a single `pledgeShareBps` value (fixture 0, matching `revenue_config.opencast_pledge_share_bps` in `docs/open-decisions.md`) and keeping the line's copy in one string.
- **Wallets for viewers** (You 01.1). Build so it's easy to change by listing sign-in methods from config (`['email','apple','google','wallet']`) passed to the Privy provider; `docs/open-decisions.md` currently defaults viewer wallets to "no", so the fixture should be able to drop "Connect a wallet" with one flag.
- **On demand** (station-pages 02.1). Build so it's easy to change by giving each episode row an empty action slot and keeping episode actions derived from one function (next airing → Remind me), so a Play action can be added without re-laying out the list.

#### Can't be built as drawn / worth raising

1. **A tally in a list** (station-pages 04.1). The tuned row on the radio band list shows a lit `tally lit` "ON AIR" instead of Tune in. The apps prompt says "On viewer screens, only the player shows a lit tally", and the note itself only asks for the tally edge. Suggest the tally edge plus no lit sign.
2. **Member count placement.** Home 03 note: the member count "only appears next to Pledge". Station page 01.1 shows "Members 214" in the About KeyValueList, away from Pledge.
3. **Mock data conflicts across files.** Home 01.1 has preset key 6 "Empty"; You 02.1/03.1 have key 6 = HALL 90.7 and "All six keys are taken". First visit 08.1 says Inland Empire has "9 stations"; home shows 6 TV + 4 radio = 10 (9 only if the listed RDLS isn't counted). Say whether listed streams count as stations.
4. **Program vs episode vs station naming.** Station REEL's name is "Saturday Reel" and it makes the program "Saturday Reel"; NITE's name is "Night Desk" and "Night Desk" is also a program (Carried widely). The player's second line says "Cartoons, 1928 to 1934" while the program page says episode 14 "River boats and paddle wheels" is on BEAT now; REEL's dial row shows "Cartoons from 1928 to 1934" 8:00–9:00 while the program page says episode 13 aired on REEL at 8:00. Presets use shortened titles ("Live Town Hall", "Radio dramas", "Slow beats") that no field holds. Decide which field feeds each line (`title`, `episodeTitle`, a short title) before building fixtures.
5. **Hero on phone vs web.** The same airing has different blurbs (web "Residents question the Planning Commission…", phone "Live from Redlands City Hall, with questions from viewers."). One description field can't give both. Also, the hero rule doesn't say whether radio-band live programs (CRAT 101.9 is live) qualify, though radio has no picture for a muted preview. It doesn't give a tie-break when several are live either (suggest channel order).
6. **"Made possible by" vs credits.** The note says underwriters are listed "exactly as they're read on air", but the frame shows only business names ("Redlands Hardware"); a `Sponsorship.creditText` is the full credit (who, where, what they do).
7. **Replace-key dialog** (You 03.1) offers only keys 3 and 6 plus "No key", with 6 preselected. Nothing says why these two. `suggestPresetKey` returns one key. Either show all six with the suggestion preselected, or the API needs a ranked list.
8. **Manage pledge** (You 04.1) draws a Monthly/Once switch, and the section lede says "Change it, pause it or stop it". No pause control is drawn, and `updatePledge` supports neither pause nor a cadence change.
9. **Pledge summary copy** "$10.00 a month goes to Inland Beat" conflicts with the ledger (`docs/architecture.md`: pledge to station "less Stripe's fee"). The note itself says "less card fees". The contract minimum is $1.00 (`Micros.min(1_000_000)`), and no error copy is drawn for Other.
10. **Share links.** `useopencast.org/beat/tonight-9pm` is a relative slug that's wrong after tonight; it needs a stable airing id in the URL. The link preview card needs server-rendered Open Graph tags, which a Vite SPA can't produce alone (needs an edge function or prerender). Station pages at `/:handle` need handles that don't collide with app routes (`guide`, `radio`, `you`, `settings`, `presets`, `program`, `search`, `tv`, `watch`). `createStation.handle` (`^[a-z0-9-]{2,30}$`) reserves nothing.
11. **Numbers tune vs preset keys.** On the web, digits 1–6 tune presets "from anywhere in the app", while the rules say typing a channel anywhere a viewer can type tunes to it. Suggest digits outside a text field are preset keys and channel numbers go through search (`/`), and write that into `rules.md`.
12. **Settings panes not drawn.** Only Watching (web) and Notifications (phone) have frames. Account, Market, TVs and casting, Appearance, Privacy and Your data exist only in a note, so their copy goes to `docs/apps/new-copy.md`. The same goes for off-air rows/player, empty You sections, no-results search, card-failed pledges and 0 device presets.
13. **"Let others on the Wi-Fi change channel"** is only enforceable on the Opencast TV app and the Cast receiver (receiver can ignore senders). AirPlay targets (drawn as "Bedroom TV, AirPlay") can't be controlled this way. **Lock-screen remote** on the web PWA depends on Media Session `previoustrack`/`nexttrack` support (partial on iOS); the full version is the Capacitor build.
14. **"Use my location"** has no endpoint that takes coordinates. Reverse-geocoding to a ZIP on the client would send location to a third party, which conflicts with "Your location is only used to pick a market and isn't stored".
15. **Thin dial mixes bands** (08.2: MOJV TV and DUST radio in one list with a "Radio band" label), while `getDial` is per band. The app needs two calls and a merge rule. The nearby block shows 3 of Inland Empire's rows, with no stated limit.
16. **Duration style.** "18 min left" (station page 01.1) and "40 episodes of 30 minutes" (program page) don't use the `:30`/`28:30` duration style in the rules. Copy is final, so this is flagged only.
17. **Privy email code lifetime.** The copy says "It works for 10 minutes". Confirm that Privy's OTP lifetime matches, since Privy owns it.
18. **Guide Presets filter** can't show presets from the other band or another market from one `getGuide` call (per market, per band).

#### Open items

#### Can't be built as drawn / worth raising

1. **Number-entry wait conflicts.** opencast-tv.html 02 note "Tune by number" says it tunes "after a second and a half"; the settings frame (update 04.1) shows the default "After typing a number, tune in: 2 seconds"; the phone keypad (06.4) counts "Tuning in 1 second". Pick one default (the setting's options must include it).
2. **Sleep timer and Pledge aren't in the menu rail.** Update 05 says the sleep timer is "in the menu rail", and tv 05 says pledge comes "from the menu or a station's info", but 04.1's rail has exactly the "Seven items" of its note (Guide, Presets, Radio band, Your market, Captions, Settings, account) with neither. Where they go needs deciding.
3. **Screens referenced but not drawn:** station info / "About Inland Beat" (03.2, and "a station's info" in 05), the Radio band item (04.1), changing market on the TV (04.1, 05.3), the reminder card at 8:59 ("Beat Tape Live is starting on BEAT 12.1. OK to switch." is copy in a note only), the four other settings sections (Remote and phones, Picture and sound, Account, About this TV), the sleep fade notice ("30 more minutes"), code expired, sign-in handoff from Remind me / Save this channel when signed out, stand by, and a sleep timer on the phone remote. All need copy from the Voice chapter → `docs/apps/new-copy.md`.
4. **Under 21px at 1080p.** The intro rule is "Nothing under 21px at 1080p", but the reference CSS has `.tv .tally` at 18px, the guide's now-line time `.gg-now span` at 20px, and the sleep options' clock times `.sleep-opts .tv-btn small` at 20px (update 05.1). Build at 21px minimum and flag the change.
5. **Watch on labels conflict.** 06.2 labels rows "Chromecast" / "AirPlay" with one "Play on Living room TV" button; the update 02 note "Choose a TV that fits" says Chromecasts say "Cast", AirPlay TVs "Mirror", TVs with the app "Open the app". 06.2 needs redrawing or the note wins.
6. **AirPlay TVs can't be listed by the app.** iOS has no public API to enumerate AirPlay receivers (AVRouteDetector only says whether any exist; the list is the system's AVRoutePickerView). "Bedroom TV, AirPlay" in 06.2 can only come from TVs remembered from earlier mirroring sessions (route port name) or from the system picker. Web PWA: Cast sender works only in Chrome; iOS Safari can't cast at all until the Phase 8 native build.
7. **"Open the app" needs to know the TV has Opencast.** Neither Cast discovery nor AirPlay says which apps a TV has. Options: the account's signed-in TVs (needs the TV registry gap below), or Cast Connect (the Android TV app registered as the Cast receiver, so casting launches the installed app). Fire TV has no Cast, so it can only come from the registry.
8. **"Pairing a phone" / "who on the Wi-Fi can change the channel" for the TV app.** A phone can't reach an Android TV / Fire TV app on the LAN from a web app; it needs either Cast Connect (Google TV / Android TV only) or a server relay with pairing (a gap below). Server-side, "same Wi-Fi" can only be approximated by the public IP. On a Cast receiver the rule is enforceable in the receiver (ignore commands from senders other than the one that started the session), with the setting sent by the casting phone (`settings.tvs.othersOnWifiCanChange`), since the receiver has no account.
9. **Names in the chip.** "Kai's phone" / "Kai's iPhone": since iOS 16 `UIDevice.name` returns "iPhone" without a special entitlement, so the name must be built from the account's display name, and `Me.displayName` is "Kai M." (a first name has to be split off). Signed-out phones need fallback copy (new copy).
10. **Menu on a basic remote: "Home".** Android TV and Fire TV don't deliver the Home key to apps (it always goes to the launcher). Only "long-press Back" is buildable.
11. **The banner covers the bug only where the bug is.** 02 note says the banner covers the station's bug. The bug is burned into the stream by the worker (architecture.md, runner.ts) at a position the station chooses (`StationSetup.bug.position`, mode can be `logo`), so a top-corner bug stays visible above the banner.
12. **Listed city streams on a TV.** RDLS 9.1 is a neighbour of CIVC 7.1 (▲ from 7.1 lands there) and its `DialRow.playback.kind` is `embed` (the city's own player). An iframe player can't be driven by the D-pad reliably, may not autoplay, and a CAF receiver can't play it through its media pipeline. Decide: skip listed stations on TV/Cast, or show a "watch on the city's player" state.
13. **Pre-warming on a Chromecast.** CAF's PlayerManager drives one media element; running three HLS players to warm neighbours is doubtful on Chromecast memory. Also, using hls.js instead of PlayerManager loses sender media status (which Android lock-screen controls and the Google Home app use). Likely: PlayerManager for the picture, pre-warm by prefetching neighbours' playlists and first segments only.
14. **Level meter and audio evening-out need Web Audio on the playing element.** Fine with hls.js/MSE in a browser or Android WebView; doubtful on a Chromecast (CPU, and PlayerManager's element), and on the iPhone external display if WKWebView falls back to native HLS (Safari's native HLS gives Web Audio silence). Use hls.js with ManagedMediaSource there, or an approximate meter where Web Audio isn't available.
15. **Lock-screen channel controls while casting on iOS** (06 note "On the lock screen"). The Cast iOS SDK doesn't provide lock-screen controls. Now Playing controls need the app to be the now-playing app (usually local audio playing). Android's Cast media notification can map next/previous to channel up/down. Mark iOS as doubtful.
16. **Battery line** (update 02.2): iOS reports `batteryLevel` in 5% steps, so "64%" can't appear on an iPhone. "About 3 hours at this rate" has to be estimated from drain over several minutes. Show nothing until there's a rate.
17. **Mirroring remote drops the presets.** 02.2 has no presets row, while 06 "Everything a remote has" says the phone remote has the six presets. Presumably the warning took the space; confirm.
18. **Hint row hiding after a week** is device-local (first-use date in storage). It must not hide the "Playing from…" / "Mirrored from…" chip or "Keep Opencast open", which are the only hint-row content on cast and mirror. Storage on a Cast receiver may not persist, so it would never hide there.
19. **Reminders on a cast TV.** A Cast receiver has no account, so the 8:59 card and switch-over only reach a cast TV if the phone forwards them (`{type:"tune"}` / a reminder message). A signed-in TV app can poll accounts.listReminders and time the card itself.
20. **"Saved to your account, so your other TVs use them too"** (update 04.1) is false on a signed-out TV and on a Cast receiver. The line needs a signed-out variant. The TV-only rows (channel up direction, banner seconds, number-entry wait, include radio band, picture quality, audio evening-out) aren't typed in `ViewerSettings`, but its `.loose()` keeps unknown keys ("so the apps can add settings"). Agree key names with the viewer app and list them in `contract-requests.md` so they get typed.
21. **Stand by** has no frame of its own ("uses the same layout with the colour bars"), and the worker already airs a stand-by slate in the stream, so the TV must not draw a second one over it. Which one shows needs deciding (and the data gap below).
22. **Off air suggestion rule unspecified.** 05.2 suggests REEL 24.1, not the next station up (RDLS 9.1). Define it, e.g. the nearest on-air, non-listed station in dial order.
23. **Pledge URL path.** "useopencast.org/beat/pledge" uses a lowercase slug; stations.getStation resolves "by id or call sign" (`stationRef`), not by `handle`. Confirm that lowercase call signs and handles resolve.
24. **Guide description on every focus.** Airing has no description, so each focus move in 03.1 would call library.getProgram. Prefetch per visible program ids and cache; listed airings show none.
25. **Mock data inconsistency (harmless):** Captions "Off" in the menu (04.1) vs "On" in settings (update 04.1). Pick one in fixtures.
26. **Drift and reduced motion.** Radio drift (05.1) is burn-in protection, not decoration. Keep it with reduced motion (it's a few pixels a minute).

#### Open items

- **A.3 (and the flow A notes) "Takedowns"**: how a rights complaint reaches a station and pulls an item from the log, including carriers. Build so it's easy to change by: driving the library row, log block and Monitor from `LibraryItem.storage.locked` and `trust.Claim.takedowns[]`, with the takedown banner as one component shared with the Rights page (part 2 covers `opencast-rights.html`).
- **B.2 "Who approves a carrier"**: automatic vs producer approval. Build so it's easy to change by: branching B.3's confirm step on `Offer.approval` (`any_station` places immediately with Undo; `i_approve` shows "Asked" from `CARRIAGE_REQUEST_LABELS`), so either default is a data change.
- **C.2 "Opencast's share"**: spot revenue cut and pool split not set. Build so it's easy to change by: keeping the notice copy with no number and rendering share/pool from `Undecided` (`notSetYet`) on earnings and statements.
- **Settings 02.1 "Political spots"**: whether political advertising is allowed at all. Build so it's easy to change by: loading the blocked-category chips from one list (a config/fixture now, an endpoint later), so "Political" can be removed or made mandatory-blocked without touching the page.

#### Can't be built as drawn / worth raising

1. **Cue a break during a carried program.** A.7 and P.1 show "Cue a break now" / "Cue a break" while Saturday Reel (carried, not live) is on air; the A.7 note says it is "For live programs" and `playout.cueBreak` is "during a live block". Build it disabled (or hidden) outside live blocks unless the design says otherwise.
2. **Station ID position.** The A.7 rundown airs SID at 8:45:00, then BMP, UND, OPEN, BMP; Settings 02.1 says "Station ID: Always last, can't be removed" and the break note says every break ends with it. One of them is wrong; the log generator should follow the settings rule.
3. **Open time doesn't add up.** C.1 says "3:30 open across 4 breaks" (and the rail badge 3:30), but its rows are 1:00 + 1:30 + 1:45 = 4:15.
4. **Spot payment cadence.** C.2 says "Paid monthly with your other spot revenue"; earnings 02.1 says spots are "settled after each airing" with a weekly payout to Chase.
5. **Who can sign off.** The team PermissionsTable (03.1) gives "Team, identity, sign off" to owners only; `playout.signOff` allows owner and operator, and the header's Sign off sits on every screen. Needs a decision; hide or disable for non-permitted roles.
6. **Browser source vs hosts.** 01.1 says the browser source is for "Owners and operators of BEAT"; hosts go live on their assigned blocks (03.1, 05.x). Already logged in `docs/open-decisions.md` (backend grants hosts go-live via `host_assignments`); the copy on 01.1 needs changing.
7. **Copy a masked key.** 01.1 shows "beat-studio-a-········ Copy", but the contract returns the key only once (on add or reset); `LiveSource.streamKeyPreview` is all that exists later. Copy can only work right after create/reset; otherwise the only path is Reset key.
8. **Listing fallback vs flag.** The listings note says an airing without its own description uses the series description; yet "Late Crate, ep. 16" is flagged "Needs a description" while ep. 15 of the same series is Complete. Decide whether a missing episode description counts as incomplete.
9. **Fixed rail vs host scope.** The rail is fixed on every screen, but a host should see only their blocks "without seeing anything else". Proposal: rail items render disabled (not hidden) for hosts with a one-line reason, or a host-only rail; needs a design call.

#### Where the permission page lives (06.1, 06.2)

Serve it from the **viewer app** at `/permission/:token`, outside the phone shell (no tabs, no mini player, no player bar):
- The API already builds the link that way: `askPermission` and `answerPermission` use `` `${deps.config.appOrigin}/permission/${token}` `` (`apps/api/src/v1/modules/network/desk.ts`), and `APP_ORIGIN` is "the viewer's URL" (`docs/deploy.md`; default `http://localhost:5174`, the viewer's Vite port).
- The desk is admin-only (every network endpoint except the two `/permission/:token` ones is `auth: "admin"`), so a creator can't reach it.
- The site is a static marketing page with no Privy; "Claim now" needs sign-in (`startHandover` is `auth: "user"`) and then master control's sign-on, which the viewer app already hands off to ("Run a station or offer your programs").
- It's a phone page first, and the viewer app is the PWA people have on phones.
Mark the route `noindex`; the token is the only credential.
